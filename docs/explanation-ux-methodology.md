# Codexplain Explanation UX Methodology

Codexplain explanation shaping follows these project defaults:

- Start with a TLDR for non-artifact explanations.
- Put the most important answer first, then evidence and next action.
- Keep related visuals spatially close: table and flow side by side when width allows, stacked when narrow.
- Prefer connected Unicode box drawings for architecture and process explanations.
- Preserve exact commands, paths, dates, test evidence, and uncertainty.

Research basis:

- Cognitive load theory: reduce unnecessary working-memory load with chunking, signaling, and avoiding split-attention.
- Multimedia learning: use coherence, signaling, and spatial-contiguity principles so labels and visuals stay close.
- Plain-language practice: organize around the reader's task, use headings and summaries, and avoid needless jargon.
- Explainable-AI caution: explanations should improve understanding without overstating certainty or creating false trust.
